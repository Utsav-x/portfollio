    01 Real-time bidding · Rarità

    Two bids. Same millisecond. One winner.

    Auctions get hammered in the final seconds. I made bid acceptance atomic, so the system can never crown two winners.

    1. Three bids land at onceAsha and Bilal both bid ₹16,000. Kabir bids ₹16,500.
    2. Naive code crowns two winnersBoth read ₹15,900, both pass the check, both are told they lead.
    3. One atomic Lua script in RedisCheck and write happen as one step. Bilal is rejected cleanly; each accepted bid gets a sequence number.
    4. Saved to Postgres, crash-safeBids drain in batches. A crash and retry inserts zero duplicates.

    03 Query optimization · Sustainext

    Half the response time. Measured.

    Slow endpoints usually come down to a few fixable patterns. Here's the one I hit most, and how I took it apart.

    1. Spot the N+1One list query, then one more per row: 51 round-trips to render a single page.
    2. Fetch it in twoselect_related and prefetch_related turn 51 queries into 2.
    3. Read the planEXPLAIN shows a sequential scan over millions of rows. A composite index makes it an index scan.
    4. Measure itAPI response times dropped about 50%, measured before and after.
